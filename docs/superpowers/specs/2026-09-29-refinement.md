# ODIN refinement experiment

User approved the proposed data-first, architecture-second improvement run on the local RTX 4070 12GB. Preserve public v0.1.0, its weights and source. No guaranteed outcome, paid compute, hosted teacher targets, or pretrained initialization.

Compare three fresh random-initialized candidates with the existing 16,384-token tokenizer and 512 context: A: original 12x512/FF1536 architecture, expanded FineWeb-Edu plus WikiText training data; B: same architecture, 80% A / 20% public TinyStories GPT4 by sampled token positions; C: 20x384/FF1344, 6 heads, same mixture as B. C has 49,069,440 parameters (verify actual count). Same optimizer, seed, batch size, and total planned tokens. Stop each at 250M tokens for a pilot; this is a noisy screening stage, not proof of architectural superiority.

Expand the already downloaded, pinned FineWeb shard to all rows. Pin TinyStories revision f54c09fd23315a6f9c86f9dc80f725de7d8f9c64, train file only, CDLA-Sharing-1.0. Public synthetic provenance must be disclosed. Reuse the original tokenizer and original development set to keep losses comparable. Exclude all document-hash development buckets from training. Protect original development 13-grams in addition to all five official benchmark validation/test splits. Exact whole-document dedup across sources; disclose limits of exact filtering. No benchmark training examples added.

Selection: use fixed held-out web and story windows plus frozen, locally authored continuation and candidate-comparison prompts, never official test scores to pick a pilot. Rank eligible pilots by average held-out NLL with 80% web/20% stories; reject nonfinite losses and severe web regression (>0.10 nats vs A). Review all generation samples, not cherry-picked ones. If the lowest-loss eligible model's repeated-4gram rate is >0.05 worse than the original baseline, select the best eligible alternative without that regression; if none pass, retain v0.1.0 and report failure. These are engineering gates, not statistically validated intelligence metrics.

Train the selected candidate to 3,000,008,704 total tokens (183106 steps x 16384 tokens; verify arithmetic before execution). Pilot is 15,259 steps / 250,003,456 tokens. Total budget including losing pilots is ~3.5B tokens. Checkpoints resume the same full-run LR schedule, avoiding an artificial pilot-end decay or warm restart. Stop on nonfinite loss, disk <8GB, or CUDA failure. Keep failed runs and measurements. An early comparison is provisional; one seed and short pilots cannot prove universal paper transfer.

Execution settings after measured throughput test: compile_model=true, deterministic=true, CUDA bf16, batch32 x accumulation1 (still16,384 tokens/step). Every candidate uses the same settings. Deterministic GPU recovery verified for both full-size architectures. Store flags in the recipe and freeze config file contents.

Final: full official evaluation, original qualitative suite plus new frozen suite, CPU throughput, side-by-side report with actual compute including pilots. Keep release v0.1.0 immutable. Promote a new version only if evidence supports improvement; otherwise report findings and leave the product on the baseline. Runtime should be estimated from the pilots, with no promise of exact duration.
